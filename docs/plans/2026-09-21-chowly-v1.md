# Chowly v1 — Implementation Plan

Full-marketplace food delivery platform: customer + rider mobile app, restaurant/admin web portal, and Node.js API.

> **Reference:** [Planning Brief](../../docs/plans/planning-brief.md) (discovery decisions)

---

## User Review Required

> [!IMPORTANT]
> This plan is organized into **10 phases** that build on each other. Each phase produces a working, testable increment. Phases 1–4 deliver a functional ordering flow; Phases 5–7 add real-time and rider features; Phases 8–10 add the admin dashboard and polish.

> [!WARNING]
> **External accounts required before Phase 4:** MongoDB Atlas cluster, Stripe account (test mode), Cloudinary account, Google Maps API key with Maps SDK, Places, Directions, and Geocoding APIs enabled.

## Phase 5 — Real-Time with Socket.IO

Set up Socket.IO infrastructure for live order status updates and rider location broadcasting.

### API

#### [NEW] [socket.config.ts](file:///d:/PROJECTS%20FILES/mern-delivery-platform/api/src/config/socket.config.ts)
- Initialize Socket.IO server, attach to Express HTTP server
- JWT authentication middleware for socket connections
- Namespace/room strategy:
  - `order:{orderId}` — all parties (customer, restaurant, rider) join for that order
  - `restaurant:{restaurantId}` — restaurant owner listens for new orders
  - `riders:broadcast:{area}` — nearby riders listen for available orders

#### [NEW] [socket.service.ts](file:///d:/PROJECTS%20FILES/mern-delivery-platform/api/src/services/socket.service.ts)
- `emitOrderUpdate(orderId, status, data)` — broadcast to order room
- `emitNewOrder(restaurantId, order)` — notify restaurant of new order
- `broadcastToRiders(area, order)` — send available order to nearby riders
- `emitRiderLocation(orderId, lat, lng)` — broadcast rider position

#### [MODIFY] [order.service.ts](file:///d:/PROJECTS%20FILES/mern-delivery-platform/api/src/services/order.service.ts)
- On order creation → emit to restaurant room
- On status change → emit to order room
